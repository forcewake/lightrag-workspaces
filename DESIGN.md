# Documentation design

## Authority and scope
This records the requested restrained public documentation direction. The product name and runtime behavior belong to PRODUCT.md. Documentation is a Read surface; it must let a new reader install, choose a corpus, make a request, and understand the compatibility boundary.

## Reading system
A compact forest-green masthead, warm near-white reading surface, quiet rules, and one open diagram express a practical technical manual. Headlines use Georgia for a distinct editorial voice; interface labels and prose use the theme's readable sans-serif stack. Monospace is reserved for code and identifiers. The first viewport names the mechanism, shows the request path, and offers an immediate installation route.

## Structure
The index is a reading map, not a dashboard: one descriptive title, concise purpose, one SVG mechanism diagram, installation and adoption links, then a compact compatibility table. The navigation follows the real task sequence: install, use, adopt, operate, understand, contribute. Every guide starts with the action or result and states prerequisites close to the relevant step.

## Assets and claims
SVGs are authored geometric diagrams with synthetic corpus names and accessible titles/descriptions. They are illustrative, never presented as deployment evidence. There are no fabricated metrics, customers, awards, production claims, or upstream endorsement badges.

## Responsive and accessibility
Navigation collapses into the theme drawer. Code examples scroll locally rather than widening the page. Tables may scroll on narrow screens. Focus rings, text selection, and reduced-motion behavior use the same palette. The diagram retains readable labels at narrow widths through a vertical mobile variant.
